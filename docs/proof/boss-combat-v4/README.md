# Подключение материалов и механик боссов

Проверена реальная финальная комната каждой из пяти миссий. Изменения описаны в `docs/gameplay/MISSION_BOSS_COMBAT.md`.

- 64/64 целевых тестов: уникальные параметры, направление рывка, попадание и уклонение, реальные потери HP, заморозка, опоры, три корня, копирование оружия, ограниченный возврат снарядов, атакующий рой, наземная фаза, зачистка после смерти, большой радиус попаданий, загрузка моделей, миссионные награды и прежние бои. Лог: `output/boss-combat-v4/tests.log`.
- Acceptance и production сборки успешны. Логи: `output/boss-combat-v4/build.log`, `production.log`. Предупреждение Vite о большом общем JS чанке остаётся.
- 15/15 проверок экранов: пять миссий при 390×844, 360×640 и 1280×720. В широком окне игровая сцена 405×720. Без горизонтального переполнения, ошибок загрузки моделей и окружения. Результаты: `viewports.json`; снимки `*-390.png`, `*-360.png`, `*-wide.png`.
- Пауза подтверждена: время и состояние Пастыря остались неизменными, `pause.json`. После исправления PMREM в финальном прогоне консоль без ошибок и предупреждений, `console.json`.
- Живой Ловчий выполнял повторные рывки. У Левиафана проверено падение скорости с 0.65 до 0.4875 после первой опоры. Собор чередует зоны и залп из пяти семян; третий корень включает вторую фазу. Сборщик выпускает залп. Пастырь выпускает четыре живые атакующие пчелы. Состояния: `actions.json`.

Начальное состояние — явно подписанный тестовый checkpoint `?review=mission-boss&mission=ID`. Предыдущие 24 комнаты помечены пройденными, герой без оружия и неуязвим. Кнопки шага атаки выполняют настоящую симуляцию; кнопка узла вызывает обычный обработчик урона. Кнопка второй фазы уменьшает HP только внутри тестового checkpoint. Это проверка интеграции и боя, а не доказательство полного прохождения 25 комнат или окончательной балансировки сложности.

Общий `npm test` на совместном рабочем дереве: 480/494 прошли, 14 упали. Эти результаты не объявляются зелёными. 13 ошибок воспроизводятся в контрольной копии с отключённой новой механикой боссов (старые UI/preview/import assertions, painted-adapter, QA pilot, navigation и event notice); ошибка first-boss из общего параллельного запуска не воспроизводится в целевом и контрольном запусках. Исходники других задач не откатывались. Логи: `full-tests.log`, `control-tests.log`, `control-events.log` в `output/boss-combat-v4`.
